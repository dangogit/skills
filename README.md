# הסקילים של אין קוד ל-Claude Code

אלה הסקילים שאנחנו נותנים לתלמידים של אין קוד (nCode). כל סקיל הוא תיקייה עם קובץ `SKILL.md`, ו-Claude Code טוען אותו לבד כשמגיעה משימה שמתאימה לו. בקורס רואים איך עובדים עם כל אחד מהם על פרויקט אמיתי, ופה מתקינים אותם ועובדים איתם אצלכם.

כל פעם שסקיל חדש מוכן, הוא נכנס לכאן. שווה לעדכן מדי פעם.

## התקנה

בתוך Claude Code (לא בטרמינל):

```
/plugin marketplace add nCode-co-il/ncode-skills
/plugin install ncode@ncode-skills
```

או מהטרמינל, לסקיל אחד:

```bash
npx skills add nCode-co-il/ncode-skills --skill client-project-proposal
```

לא צריך חשבון מיוחד או הזמנה. הריפו ציבורי, וכל אחד יכול להתקין ממנו.

## מה יש כאן

| סקיל | מה הוא עושה |
|---|---|
| `client-project-proposal` | לוקח פגישה, הודעות ואפיון של לקוח, מעריך כמה ימי עבודה זה, ומוציא הצעת מחיר PDF ממותגת בעברית. |
| `ship-ticket` | לוקח משימה מ-GitHub ומביא אותה עד PR פתוח: תופס אותה בלוח, בונה עם טסטים, מריץ בדיקות, עושה code review, דוחף ומעדכן את המשימה. |

## הצעת מחיר ללקוח

נותנים לסקיל את החומרים של הלקוח, והוא:

1. קורא את התמלול, ההודעות והאפיון, ושואל רק את השאלות שמשנות את המחיר.
2. מפרק את העבודה לשלבים ומעריך כל שלב בימי עבודה. הימים והמחיר ליום נשארים אצלכם.
3. בונה הצעה ללקוח: מה כואב לו היום, מה המערכת עושה, שלבים עם תאריכים, לוח זמנים, מחיר כולל אחד, תנאי תשלום, מה כלול ומה לא.
4. מרנדר PDF בעברית מימין לשמאל עם הלוגו והצבע שלכם, ובודק כל עמוד לפני שהוא מחזיר אותו.

הוא לא שולח כלום ללקוח ולא מתחיל עבודה. את ההצעה אתם קוראים, מאשרים ושולחים.

### לפני הפעם הראשונה

פתחו את `references/defaults.md` בתוך הסקיל ומלאו את מה שבסוגריים מרובעים: השם שלכם, פרטי העסק, המחיר ליום עבודה, הלוגו, צבע המותג ואיפה לשמור הצעות. אם לא תמלאו, Claude ישאל בפעם הראשונה וימלא בעצמו.

באותו קובץ יש ברירות מחדל שאנחנו ממליצים עליהן, ואפשר לשנות כל אחת:

- הלקוח רואה מחיר אחד לכל המערכת, בלי מחיר לכל שלב ובלי ימי עבודה. ככה אי אפשר לחשב ממנו את המחיר שלכם ליום.
- 50% לפני שמתחילים, 50% במסירה.
- 30 ימי הרצה אחרי המסירה כלולים במחיר, לתיקוני באגים והתאמות קטנות.
- לכל שלב יש תאריכים, מתאריך התחלה שכתוב בהצעה.
- ההצעה לא מזכירה באילו כלים אתם בונים.

### איך משתמשים

כותבים ל-Claude משהו כמו:

```
תכין הצעת מחיר ללקוח לפי התמלול ב-meeting.md והאפיון ב-docs/spec.md
```

או מפעילים ישירות עם `/ncode:client-project-proposal`.

### מה צריך במחשב

- Google Chrome, בשביל לרנדר את ה-PDF. בלינוקס או בנתיב אחר מעבירים `--chrome`.
- poppler, בשביל לבדוק את העמודים: `brew install poppler` במק.
- Python 3.
- רק אם רוצים קובץ Word במקום PDF: `python3 -m pip install python-docx`.

## ממשימה ל-PR

אומרים ל-Claude "קח את המשימה הבאה" או "תעבוד על #12", והוא עובד לפי סדר קבוע:

1. בוחר משימה מוכנה בלי חסימות, או את זו שביקשתם, וקורא אותה עד הסוף.
2. תופס אותה בלוח (In progress) לפני שהוא נוגע בקוד, כדי ששני סשנים לא ייקחו אותה.
3. פותח branch משלה, בונה עם טסטים קודם, ומריץ את כל הבדיקות של הפרויקט.
4. עושה code review על השינוי, מתקן את מה שנמצא ומריץ שוב.
5. דוחף, פותח PR עם `Closes #N`, מסמן את מה שנבדק במשימה ומעביר אותה ל-In review.

הוא לא עושה merge בלי שאמרתם לו, ולא משאיר משימה בסטטוס שלא מתאים למה שקורה בפועל. אם משהו חוסם אותו מבחוץ, הוא מסמן Blocked, כותב מה חסר ועובר למשימה הבאה.

הסקיל עובד הכי טוב יחד עם [הסקילים של Matt Pocock](https://github.com/mattpocock/skills): `tdd` לבנייה, `code-review` לביקורת ו-`pr` לתיאור ה-PR. בלעדיהם הוא עושה את השלבים האלה בעצמו.

### לפני הפעם הראשונה בפרויקט

הסקיל קורא את `CLAUDE.md` של הפרויקט כדי לדעת איך בוחרים משימה, איך מסמנים סטטוס, איך קוראים ל-branch ואילו בדיקות להריץ. אם אין שם כלום, הוא משתמש בברירות מחדל של GitHub ומציע להוסיף לפרויקט סעיף "Ticket workflow" קצר. הוא כותב אותו רק אם אישרתם.

### איך משתמשים

```
קח את המשימה הבאה מהלוח
```

או מפעילים ישירות עם `/ncode:ship-ticket`.

### מה צריך במחשב

- `gh` מחובר לחשבון GitHub. ללוח של GitHub Projects צריך גם הרשאת project: `gh auth refresh -s project`.
